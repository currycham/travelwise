# TravelWise · 找到自己的旅行方式

延续 WayWise「认得路，也会找路」的理念。AI 帮用户看见旅行的可能和代价，用户通过比较、修改和回望，逐渐知道自己想怎样旅行。

## 本机运行

Node.js 22+，无第三方运行依赖，无境外 CDN。

```sh
cp .env.example .env
# 在 .env 中配置模型接口；不配置也可体验编辑示例
npm run dev
```

本机访问 http://127.0.0.1:8600 。线上地址：https://travelwise.waywise.tech 。服务器仅监听 127.0.0.1:8600，由 Caddy 提供 HTTPS。

模型配置经用户授权从 SportsWise 复用，并已获单独授权用于 TravelWise 生产服务器。没有复制其他业务凭据，没有修改其他产品。`.env` 已忽略，文件权限 0600，不进入提交。不要用示例配置覆盖已配置的 `.env`。

## 已实现

- 邮箱验证码登录 / 注册，同一已验证邮箱识别 Waywise 其他产品账号；访客仍可使用，登录时可显式迁移本机记录。
- 登录后云端保存偏好、收藏、手记、当前草案，生成历史自动留档；新生成可参考旅行记忆或关闭记忆。
- 有目的地 / 从旅行期待出发的两种输入；2–21 天天数范围、出发地、大致时间、每人预算、同行者、兴趣、过往经历、喜欢与回避、身体或出行限制和取舍重点。
- 三步梳理期待，真实模型生成一套或两套完整草案；方案说明适合原因、获得与放弃的体验，以及让用户权衡的问题。两案要求在至少两个维度有实质差异。
- 逐日地点与活动、区间移动、抵离缓冲、天气或体力不足的替代、当日反思问题；另含往返交通、住宿片区与类型、餐饮、每人分类预算、行前核对。
- 可以修改活动与交通、改成自由时间、修改预算、撤回最近一次修改、写选择理由。已收藏的修改同步保存。
- 访客的当前草案、收藏、期待及手记保存到浏览器 localStorage；登录后账号数据保存到云端并有独立本机缓存；Markdown 导出包含完整交通住宿、每日活动、预算、核对事项和选择理由。
- 旅行手记记录喜欢、疲惫和下次想保留的选择；用户主动点击后才带入下一次旅行输入。
- 杭州、泉州、大理三份编辑示例，明确来源，与真实模型输出分开标注。
- 手机和桌面适配、键盘焦点、表单标签、状态提示、无 CDN SVG 插画。

## 模型接口

配置 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`；基于供应商兼容的 `/chat/completions` 接口。模型须支持 JSON response format。名称应使用供应商当前可用模型。

访客只发送本次旅行输入。登录用户开启旅行记忆时，额外发送明确填写的旅行偏好、最近五条手记与选择理由、最近三次规划的简要摘要；不发送邮箱、验证码、会话或其他产品业务内容。草案不视为已经到访，本次要求优先于历史。模型供应商的数据处理政策仍然适用。

`accounts.sqlite` 保存账号、资料和历史；`usage.sqlite` 单独记录不含旅行内容的调用用量。两者均为服务端可读数据，不提供端到端加密。可以导出、删除账户，服务器备份保留最近 14 份。

一次生成含至多一次结构或预算修正，共享 180 秒超时，前端等待上限 190 秒；每次模型调用分别占用额度并记录用量。按 Asia/Shanghai 自然日默认全站 30 次、同一网络 5 次，每次间隔 5 秒，同时最多一个请求；计数持久化，重启不清零，失败尝试也计数。生成错误不覆盖已有计划。用量记录没有擅自猜测金额：cost 为 null，cost_basis 为 unpriced；还没有接入统一成本采集。程序检查方案数量、天数、信息结构、预算非负与总额上限；语义上的限制仍需用户核对。

## 验证

```sh
npm run check
npm test
# 服务启动后，无额外模型费用
node scripts/http-check.mjs
```

浏览器验收脚本 `scripts/browser-check.mjs` 需要独立 Chrome CDP 端口 9227；它会清空该隔离浏览器里的 TravelWise 数据，勿在个人浏览器会话运行。覆盖输入、来源标注、收藏、编辑、撤回、预算、核对、手记、带入下次期待、刷新保存及 1440 / 390 像素布局。截图在 `docs/screenshots/`。

设计验收脚本 `node scripts/design-browser-check.mjs` 使用相同的隔离浏览器，覆盖 1440 / 1024 / 768 / 390 像素布局、思考提示、当前步骤、键盘跳转、登录弹窗及等宽方案比较。不发邮件、不调用模型；也会清除隔离浏览器在受测站点的本机记录。默认访问本机服务，可通过 `CHECK_ORIGIN=https://travelwise.waywise.tech` 检查线上。2026-11-14 改版的本机与线上验收均已通过，`npm test` 当前为 9 项全部通过。

真实模型验收使用虚构资料，样本保存在 `docs/live-generation-sample.json`。不包含个人资料或密钥。详细范围见 `docs/验收记录.md`。

## 当前边界

已部署到 travelwise.waywise.tech。已支持跨设备保存与同邮箱产品关联；尚无跨产品免再次验证的统一会话、实际预订、实时旅游检索、酒店库存或票价查询。金额是规划估算，模型给出的时间与可达性也需核实，行前核对不能当作系统已订妥。没有自行读取用户真实旅行史。

生产服务保持 `HOST=127.0.0.1`，由独立 Caddy 片段代理。本站允许免登录体验，也支持邮箱验证码登录后的独立云端档案。已补充生产 HTTPS Origin 检查、持久化站点与网络额度、匿名用量记录、systemd 自启和每日备份；账号按已验证邮箱与现有产品关联，各产品会话独立；跨产品单点登录和统一成本采集仍由共用后台后续集成。

## 自有服务器部署

`bash deploy/deploy.sh --setup` 首次安装独立 travelwise 用户、systemd 服务、Caddy 片段和每日 SQLite 备份；后续用 `bash deploy/deploy.sh`。生产 `.env` 只在服务器配置，不由部署脚本覆盖，也不经 rsync 上传。默认复用已登记的服务器 SSH 主机密钥；可通过 `DEPLOY_HOST`、`DEPLOY_KEY` 和 `DEPLOY_HOST_KEY_ALIAS` 指定已知目标。

部署与统一后台对接信息见 `docs/部署与集成.md`。

2026-11-14，用户明确授权模型密钥用于生产，线上 AI 已开启，并通过公网真实生成验收。部署环境仅更新模型字段，保持生产密钥文件 0600；密钥未进入源码或输出。详见 `docs/部署与集成.md`。

## 邮箱账号与旅行记忆

生产设置 `ACCOUNT_BRIDGE=1`，仅通过权限为 root:travelwise 0660 的本机 systemd socket 调用受限账号桥接。桥接使用现有 SportsWise SMTP 配置发固定验证码邮件，查询由独立只读任务生成的其他五个产品同邮箱哈希索引；没有向 TravelWise 复制 SMTP 密钥，也不导入其他产品业务资料。`NoNewPrivileges` 保护保持开启。

验证码十分钟过期、五次尝试、六十秒重发间隔，发送额度持久化；会话仅存 token 哈希，生产使用 Host-only Secure HttpOnly Cookie。云端保存带 revision 冲突检查，未同步修改保留在原账号缓存中；退出恢复独立访客空间。

`npm test` 包含本机模拟接口集成测试，需要允许监听回环端口，不发送真实邮件或调用真实模型。`scripts/account-browser-check.mjs` 使用独立临时数据和测试验证码验收迁移与跨浏览器恢复。`scripts/production-account-check.mjs` 只能在生产主机以 travelwise 用户手动执行，会使用一次真实模型生成但不发邮件，完成后删除测试账号。
