## 代码与数据检查

- `npm run check`：服务端与前端 JavaScript 语法通过。
- `npm test`：5 组程序校验通过。覆盖非法天数、预算、空期待、明确目的地缺失、目的地模式切换、方案数量、完整逐日结构、缺失替代方案、超预算、负数和文本金额；不将结构校验称作旅行事实审核。
- `node scripts/http-check.mjs`：首页和全部主要资源 200，缺失文件 404，编码目录穿越 404，异源提交 403，无效输入 400。此检查不调用模型。

## 浏览器流程

内置浏览器控制两次超时后，改用单独的无头 Chrome 临时配置进行验收，没有连接用户日常浏览器资料。

`node scripts/browser-check.mjs` 已通过：

1. 三步填写期待、出发地、过往经历与限制。
2. 查看明确标注来源的杭州编辑示例，不把它当成个性化生成结果。
3. 收藏、写选择理由、把活动改成自由时间、撤回修改。
4. 编辑活动标题与内容、按核实结果修改预算、勾选核对事项。
5. 从收藏进入旅行回望，保存喜欢、疲惫与下次期待。
6. 主动把手记带入下一次输入。
7. 刷新后核实收藏、修改、选择理由和手记保留。
8. 1440 像素桌面与 390 像素手机布局；手机端按实际 390 像素检查横向溢出，已修复网格子元素最小宽度导致的页面放大。

截图在 `screenshots/desktop.png`、`plan.png`、`mobile.png` 与 `mobile-plan.png`。

验收脚本使用虚构资料，结束时清除隔离浏览器的测试记录。

## 真实模型

经用户授权，仅复用 SportsWise 的模型相关配置。`/api/status` 返回模型已配置；虚构的上海到杭州期待已通过真实模型接口生成两套各三天的完整草案，用时约 14 秒。样本为 `live-generation-sample.json`。

首轮结果两案在体验上的差异偏小，已加强生成要求：多方案至少在两个维度有明显差异，且说明相对另一方案获得与放弃的价值。没有目的地时优先给不同目的地。

## 限制

- 未检索实际日期的票价、天气、酒店库存、开放与预约；样本中的金额和移动时间均为模型估算，不能作为已核实事实。
- 未做真实预订、发送邮件、上线部署或修改其他产品。
- 未覆盖 21 天长行程、跨境签证、复杂身体限制和所有浏览器。结构通过不代表地理路线或特殊限制已获人工专业审核。
- 账号与跨设备同步尚未接入，模型计数为进程内本机保护，不能作为正式计费。

## 无目的地真实网页闭环

`node scripts/generation-check.mjs` 已通过真实网页三步输入 → 模型生成 → 对比 → 选择 → 收藏。虚构输入为上海出发、4–5 天、每人 5000 元、看山水和当地生活、不自驾、每天步行不超 5 公里、不重访杭州与苏州。

返回两个不同目的地：浙江台州临海市与浙江绍兴新昌县。前者侧重古城生活与江边散步，后者侧重山景与村落、需要接受更多打车和较少夜间选择。结果保存在 `live-discovery-sample.json`，页面截图为 `screenshots/ai-comparison.png` 和 `screenshots/ai-plan.png`。

这项检查会实际产生一次模型调用，仅在需要复验真实生成时手动运行，不包含在常规测试里。样本是模型建议，未据此补称任何实时交通或景区信息已获验证。
