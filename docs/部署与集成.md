- 更新：本机 `bash deploy/deploy.sh`，只重启 TravelWise。
- 程序回滚：部署前的代码快照为 `/srv/travelwise/backup/app-before-deploy.tgz`（首次部署无旧版本）；先检查该归档，再恢复对应文件并重启 TravelWise，保持服务器 `.env` 和 data 不变。

## 邮箱账号上线

已安装并启用 `travelwise-accounts.socket` 与按连接启动的 `travelwise-accounts@.service`。根用户拥有的固定 Python helper 只支持发六位验证码或返回同邮箱关联产品名；没有任意模板、路径或 SQL 入口。主产品保持非特权用户与 NoNewPrivileges。

SMTP 已完成证书校验的 TLS 登录与 NOOP，不发送测试邮件；关联桥接已只读识别管理邮箱在 ReadWise、InvestWise、SaveWise、LearnWise、SportsWise 五家的账号。验证码实收需由用户主动点击获取后确认，不伪称已完成邮箱投递验收。

账号与云端历史上线后，需要定期备份 `accounts.sqlite`；脚本已覆盖两类数据库。删除账号立即清除在线数据并撤销全部会话，离线备份随最近 14 份轮换清除。

关联索引采用 `travelwise-identity-refresh.service/.timer` 每五分钟运行固定只读查询，只读取各产品的邮箱身份列、过滤停用或演示账号，输出 HMAC 哈希到根用户私有目录 `/var/lib/travelwise-identity`。桥接保持 ProtectSystem=strict，既不直接查询其他数据库，也没有它们的目录写权限。已以非特权应用用户验证完整可用，并再次通过索引匹配五个产品。

生产临时虚构账号已通过公开 HTTPS 的验证登录、云端资料写入/读取、带记忆的真实模型生成及自动历史留档；生成三天草案，测试账号及全部会话和历史已清理。没有发送真实邮件。两类数据库 integrity_check 均返回 ok。公网登录窗口桌面与 390px 手机布局已核对。
